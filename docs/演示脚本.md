## 口播全文

[0:00] 各位老师同学好，我们是十三班第六组。今天汇报的题目是数据结构知识图谱。课程里的算法和知识点比较零散，我们做了一张可以点、可以搜、可以顺着依赖往下钻的知识网络。接下来六分半，我按需求、功能、技术、协作和心得几个部分，完整过一遍。

[0:30] 先看需求文档，一共六块。背景目标说明为什么做；知识原理讲算法之间的依赖怎么建模；主要功能列出检索、浏览和详情三类操作；可视化设计定下图谱布局和配色；技术方案写清楚怎么跑起来；团队分工标出五个人各自的分支。这六块也是我们后面答辩的索引。

[1:00] 现在切到浏览器首页。主视图是一张力导向图，节点是算法，连线是依赖。我先滚动滚轮缩放，再用鼠标拖动画布，把关联紧密的一组节点拉到中间看。节点不少，但没有糊成一团，不同层用了不同颜色。左侧统计栏写着，76 条算法，33 条精讲，覆盖 13 章，分成 5 层，32 条依赖边，87 张配图，源码一共 7174 行。这些数字都从数据文件实时算出，没有写死在页面上。接着演示检索。鼠标移到检索框，输入二分，回车。命中节点立刻高亮成亮色，周围节点自动淡化，依赖路径一眼就能看清。现在换成图上不存在的词，输入量子，再回车。没有命中，页面给出空结果提示，同时所有节点恢复淡化，不会出现乱跳的假匹配。然后点顶部导航的 /all，进入全量列表。列表按章节分组，每行都有算法名、所属层和精讲标记，上方还能按章节筛选，点某一章就只看这一章的算法。我点开其中一条跳到详情页。上半部分是源码，能看到完整实现和逐行注释；下半部分是运行状态，这里备好了一组示例数据，点运行，输出区直接给出结果。运行区还能改输入参数，多试几组，输出会跟着变。从图谱到列表再到源码，路径是通的。

[3:00] 接下来讲技术方案。整个项目不需要安装任何第三方框架。后端只用了 Python 标准库里的 http.server，一条命令就能把服务起起来，终端会打印监听端口，浏览器打开本机地址就能看到首页。前端是纯 HTML、CSS 和 JS，没有引入任何 CDN，断网也能完整演示，教室网络不稳定时这一点特别实用，我们拔掉网线刷新过，图谱和检索照常工作。数据这层更关键。所有算法、精讲、章节、配图和依赖边，都放在 data 目录下的 json 文件里，这是唯一的数据入口。每个节点都带章节、层级、精讲链接和源码位置，字段含义写在文档里。页面上的统计数字、图谱节点和检索结果，全部从这些文件读取。要新增一个算法，只要改 json，不用碰页面代码。数据和展示彻底分开，改数据不会把界面改坏。部署也简单，整个目录拷到任何一台机器上，起一个静态服务就能跑。

[4:30] 再说协作。我们按功能拆了五个 feature 分支，每个人在自己的分支上开发，前后提了五个 PR，代码都经过至少一个人看过才合进主分支。每个人只动自己那一块，出问题也好定位。中间真的撞过一次冲突，两个分支同时改了数据文件里的同一个字段。处理方式是先把最新的主分支拉下来，在自己的分支上变基，然后逐个区块比对，留下两份改动里都正确的部分，再跑一遍检索和图谱页面，确认没有把别的地方改坏。冲突当天就解决了，没有影响后面的录屏安排。这次解决过程，留在了那个 PR 的讨论记录里。

[5:30] 最后聊聊 Vibe Coding 的心得。AI 帮我们快速搭起页面骨架、统计函数和第一版样式，这部分大概占六成，尤其是重复代码，写出来就能跑，AI 给的第一版方向基本是对的。人工修正主要用在三个地方，数据口径的校对，图谱交互的细节，还有依赖边的准确性。举个真实的坑。AI 生成的检索高亮逻辑只给命中节点加了高亮样式，却没在切换关键词时把上一次的状态清掉。结果连续搜两次，整张图全是亮的。我们是手动测试连搜两次才抓到的，最后在每次搜索前先统一重置所有节点状态，才算修好。AI 负责速度，人负责边界情况。我的汇报到这里，谢谢各位老师。
