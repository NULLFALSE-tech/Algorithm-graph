## 口播全文

[0:00]
老师好，我们是 13 班六组，这次作业的题目是数据结构知识图谱。选这个题，是因为课本里的数据结构本来就互相依赖，用一张图来讲，比用目录来讲清楚得多。接下来六分半，我一边操作一边说明。这段视频不留剪辑，屏幕上看得到的地方我都会指到。

[0:30]
先说需求文档，全篇分六块，背景目标，知识原理，主要功能，可视化设计，技术方案，团队分工。这六块不是凑数的标题，每一块都对应仓库里的具体文件和具体负责人，谁写哪一块，文档里写着名字，进度也在里面。文档就放在仓库里，随时能点开看，不是交上去就没人翻的附件。

[1:00]
这是首页，也是整张图谱的全貌。76 条算法，按 13 章归位，分 5 层摆放，32 条依赖边把它们连成一张网，谁依赖谁，顺着线就能看出来。滚轮缩放，按住左键拖拽平移，鼠标停在节点上会亮出它的入度和出度，点一下就直接进详情页。图可以缩到最小看骨架，也可以放到最大读某一章的细节。

页面顶部是检索框。我输入 二分，回车，命中的节点变成亮色，没命中的整体淡下去，视线自然落到结果上。再输一个库里没有的词，比如 红黑树排序，整张图变灰，页面提示没有命中，它不会为了画面好看，硬塞给我一个结果。检索在前端算，没有后端接口，敲下回车那一刻结果就出来。

切到 /all，这里是全量列表。算法按章节分组，每行写清名称，层级，依赖条数，点任意一行，视图直接跳回图上对应的节点，列表和图读的是同一份数据，不会出现两个说法。列表可以按章节折叠，也可以一键展开全部。

最后进一个详情页。上半屏是源码，关键行标了颜色，可以逐段读。下半屏是运行状态，填一组样例数据，点运行，输出结果马上出来。87 张配图挂在页面里，33 条精讲写在最需要解释的那几段，长页面不至于读到一半就断掉。详情页的地址是固定的，复制链接发到群里，别人打开就是同一页。

[3:00]
技术方案先说一条底线，这套东西断网也得能演示。后端只用 Python 标准库里的 http.server，一个框架都没有，交上去不用装任何依赖。前端是纯 HTML，CSS，JavaScript，一个 CDN 都不引，所以拔掉网线，按刷新，页面照常打开。

数据只有一个入口，data 目录下的 json 文件。页面里不写死任何一条算法，改 json 就等于改页面内容，加一条新算法只需要动一份数据。全站源码 7174 行，这个数字是脚本数出来的，不是拍脑袋估的。

为什么不上框架。因为要交的是在别人电脑上能跑的东西，不是只能在我电脑上跑的东西。老师双击一个启动脚本，浏览器打开就能看，装环境这一步直接省掉，演示现场也不会卡在配置上。启动脚本只有一行命令，端口写在里面，不熟悉命令行的人照着念也能跑起来。

json 的字段做了统一命名，前端读的时候不用为每个文件写一套解析，加一种新内容也不用改页面。

[4:30]
协作部分。我们开了 5 个 feature 分支，提了 5 个 PR，一人一条线，互相不踩脚。每条分支只动自己负责的那几个文件，改完提 PR，等审，等合并，主分支始终是能跑的状态。PR 里写清改了什么，为什么改，审的人不用逐行翻代码也能判断。

中间撞了一次真实冲突。两个人在同一个 data 文件里各加各的条目，提交的时候 Git 把两边的内容并排摆出来。我们坐下来一条一条对，字段对得上就留，对不上就补，最后把整份 json 重新校验一遍才提交。这次冲突怎么处理的写进了仓库的记录，没有藏着。

[5:30]
最后说 Vibe Coding。这次的分工很清楚，AI 负责快，人负责对。骨架，样板代码，重复的样式，成片的增删改查，交给它，省下来的时间用来想结构，想交互，想数据怎么组织，这部分它替不了人。

它也错过。边表是它生成的，有三条依赖边的方向反了，图上看不出来，拓扑排序直接报环。人对着课本目录一条条核了 32 条边，才把这三条揪出来。它擅长写看起来对的代码，不擅长判断这些代码在真实数据上对不对。所以我们的规矩是，AI 产出的东西必须能验证，验证不了的部分不写进结论。

片子到这里，谢谢老师。
