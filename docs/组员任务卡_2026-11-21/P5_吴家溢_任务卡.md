## 三、可复制给 AI 的提示词

```text
给「C 语言算法知识图谱」项目写一段 6 分 30 秒的录屏口播稿。

【片子结构，时间码不许改，共 6 段】
0:00–0:30 开场：小组与选题（13 班 3 组，C 语言算法知识图谱）
0:30–1:00 需求文档六块结构：背景目标 / 知识原理 / 主要功能 / 可视化设计 / 技术方案 / 团队分工
1:00–3:00 功能实操：首页图谱、首页检索（命中高亮 + 未命中淡化）、/all 全量列表、详情页源码与运行状态
3:00–4:30 技术方案：Python 标准库 http.server、纯 HTML/CSS/JS 无 CDN 可断网演示、data/*.json 单一数据入口
4:30–5:30 Git 协作：两阶段共 15 个分支（第一阶段 10 个 + 第二阶段 5 个）、5 个 PR、一次真实冲突的解决记录
5:30–6:30 Vibe Coding 心得：AI 生成与人工修正各占什么、举 1 个 AI 出错被人工抓到的真实例子

【真实数据，必须准确使用，一个都不许改】
76 条算法 / 33 条精讲 / 13 章 / 5 层 / 32 条依赖边 / 87 张配图 / 源码 7174 行

【要求】
- 按「时间码 | 画面（我在屏幕上操作什么）| 口播（我念什么）」三列表格输出
- 口播按每秒 4 个字控制长度，总字数 1400–1600 字，不许超
- 口播用口语，短句，不念 Markdown 符号，不说「如图所示」「大家可以看到」
- 画面列要写具体动作，例如「鼠标移到检索框，输入 二分，回车」
- 每个时间码单独一行，不许合并

【输出格式】
第一部分：Markdown 三列表格，6 行，对应 6 个时间码。
第二部分：标题写「## 口播全文」，下面输出连续的口播段落，按时间码分段，每段前标 [0:00] 这类时间码，供直接照着念。
不要解释，不要写「以下是」。
```

## 四、自己检查（提交前逐条过）

| # | 怎么查 | 通过标准 |
|---|---|---|
| 1 | 时间码个数 | 恰好 6 个：0:00 / 0:30 / 1:00 / 3:00 / 4:30 / 5:30，最后一段到 6:30 |
| 2 | 表格列数 | 3 列：时间码 / 画面 / 口播；6 行数据 |
| 3 | 总字数 | 数一下「口播全文」那部分，1400–1600 字之间 |
| 4 | 搜「如图所示」「大家可以看到」 | 搜不到 |
| 5 | 搜 76 / 33 / 13 / 5 / 32 / 87 / 7174 | 至少出现 76、33、13、32 这几个，且数字正确 |
| 6 | 画面列 | 每格都是具体动作（例如「输入 二分，回车」），不能写「展示检索功能」这种空话 |
| 7 | 文件名 | 是 `docs/演示脚本.md`，在 docs 目录下，不是在根目录 |

## 五、验收提示词（把稿子贴给 AI）

```text
你是课程作业的验收员。下面是一份 6 分 30 秒录屏口播稿，逐条检查，给 PASS 或 FAIL。

1. 必须有 6 个时间码段落，起止依次为 0:00–0:30、0:30–1:00、1:00–3:00、3:00–4:30、4:30–5:30、5:30–6:30。少一段、顺序错、时段长度不对即 FAIL。
2. 必须有一张 3 列表格：时间码 | 画面 | 口播，且 6 行数据。列数或行数不对即 FAIL。
3. 必须另有一段「口播全文」，按时间码分段，可直接照念。缺失即 FAIL。
4. 口播全文总字数必须在 1400–1600 之间。超出即 FAIL，并给出实际字数。
5. 出现「如图所示」「大家可以看到」「我们将会」「旨在」即 FAIL，列出原句。
6. 画面列每一格都必须是具体操作动作。出现「展示检索功能」「介绍技术方案」这类没有动作词的空话即 FAIL，并指出是哪一行。
7. 下列数字必须出现且正确：76 条算法、33 条精讲、13 章、32 条依赖边、87 张配图、7174 行源码。缺失或写错任何一个即 FAIL。

输出格式：一张 3 列表格「条目 | 结果 | 问题位置」，最后一行写「PASS n 条，FAIL m 条，结论：可提交 / 需返工」。
不要复述标准。
```
