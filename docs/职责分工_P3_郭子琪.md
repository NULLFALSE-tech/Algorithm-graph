## 二、「处理」这一段必须照代码写，不许猜

这一段是四步里唯一有技术含量、也最容易写错的地方。**真实实现**（`eg/store.py` 第 96 行 `search()`）是这样：

- 参与匹配的是 **5 个字段拼成的一个大字符串**：算法中文名、英文名（`stem`）、一句话简介、源文件名、章节中文名
- 匹配方式是**子串包含**（`q in haystack`），**大小写不敏感**（两边都转小写）
- **没有相关度排序，也没有条数截断** —— 命中多少返回多少，按数据里的原始顺序
- 搜索框为空时，只按章节筛选

自己去看一遍再写：

```bash
sed -n '94,120p' eg/store.py
```

> ⛔ **千万别写成「按相关度排序」「取前 N 条」**——那是别的系统的做法，我们这里没有。
> 老师演示时会照着你的文档点，写了点不出来就露馅。
> 如果之后代码改了，**以代码为准改文档**，不要为了文档去改代码。

**顺带一个能加分的细节**：说明「为什么不做排序」——因为数据只有 76 条，全量返回也就一屏，
排序的收益小于它带来的复杂度。这种「知道什么时候不做」的判断，比堆功能更能说明你在设计。
