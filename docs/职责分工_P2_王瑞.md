## 二、这一章必须写到的四件事（按这个顺序写）

### ① 算法复杂度：怎么衡量「快」和「省」

要写出这几点：

- **大 O 记号是被用来干嘛的**：它描述的是「输入变大时，耗时的**增长趋势**」，不是精确的秒数。所以 `O(n)` 不代表「跑 n 秒」。
- **为什么可以忽略常数和低阶项**：`3n² + 5n + 100` 记作 `O(n²)`，因为 n 很大时 n² 项压倒一切。配一个具体数字讲更清楚（比如 n=10000 时，`3n²=3亿`，`5n=5万`，差 6000 倍）。
- **时间复杂度和空间复杂度分别衡量什么**：时间是运算次数，空间是额外占用的内存（不含输入本身）。
- **常见量级从快到慢**：`O(1)` < `O(log n)` < `O(n)` < `O(n log n)` < `O(n²)` < `O(2ⁿ)` < `O(n!)`。说一句「前面的能跑大数据，后面的 40 个元素就爆」。
- **每个量级都举一个本项目里真实存在的算法**。下面这张表是**从 `data/algos.json` 里挑出来的真实算法名**，照抄，别自己编、别改字：

| 量级 | 用哪个算法举例（必须是主干 33 里有的） | 为什么是这个量级 |
|---|---|---|
| `O(1)` | 数组基本操作 | 按下标取元素，地址直接算出来 |
| `O(log n)` | 二分查找 | 每次砍一半，最多 log₂n 次 |
| `O(n)` | 单链表操作、二叉树层序遍历、计数排序 | 每个元素走一遍（计数排序严格说是 `O(n+k)`，k 是数值范围，范围不大时可看作 O(n)） |
| `O(n log n)` | 快速排序、归并排序、堆排序 | 每层 O(n)，共 log n 层 |
| `O(n²)` | 冒泡排序、插入排序 | 双层循环 |
| `O(2ⁿ)` | 子集和 I、汉诺塔 | 每个元素「选/不选」两种可能 |
| `O(n!)` | 全排列 I | n 个位置轮流当第一个 |

> 写的时候一句话带过即可，比如「冒泡排序是 O(n²)，因为它是双层循环；二分查找是 O(log n)，因为每次砍一半」。
> **不要给每个算法展开讲**——这一章是知识原理，不是算法课。

### ② 两种存储结构：顺序 vs 链式

这是整章的核心，要讲成一个「权衡」而不是两个定义：

| | 顺序存储（数组） | 链式存储（链表） |
|---|---|---|
| 内存布局 | 一整块连续内存 | 节点散落，靠指针串起来 |
| 找第 k 个 | **O(1)**（地址能直接算出来：基址 + k × 元素大小） | **O(n)**（只能从头一个个走） |
| 中间插入/删除 | **O(n)**（后面的元素都要挪位） | **O(1)**（改两根指针，前提是已经站到那个位置） |
| 代价 | 要预先占一块够大的连续空间，扩容得整体搬迁 | 每个节点多存指针，且内存不连续、缓存不友好 |

一句话总结（**这句要写进去**）：**「用内存的连续性换访问速度，或者用指针的灵活性换插入速度，没有白拿的好处。」**

再补一段：栈和队列**两种都能实现**（数组版 / 链表版）；哈希表底层是**数组**加冲突处理。这样读者能看出「后面的结构都建在这两种之上」。

### ④ 为什么 13 章之间的关系是「有向无环图」

- **有向**：依赖有方向。「学动态规划之前得先会数组」成立，反过来不成立。
- **无环**：不存在「A 依赖 B，B 又依赖 A」这种死锁。
- **举一条真实的依赖链**：数组 → 链表 → 栈 → 递归 → 分治 → 动态规划。
- **无环带来什么好处**：可以拓扑排序，所以能算出一条「从易到难的学习路径」，这正好是本项目按层铺开的理论依据。
- **数据佐证**：13 章、**32 条依赖边**（`data/deps.json`），自检脚本第 6 项就在查有没有环。
