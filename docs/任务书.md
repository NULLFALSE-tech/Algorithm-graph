# 任务书 · 四步走

> 这是你唯一需要读完的文件。四步做完，这门课的 Git 30 分 + AI 25 分就落袋了。
> 卡住超过 15 分钟就截图发群里，别自己硬扛。

---

## 总览：四步，一周内走完

| 步 | 做什么 | 谁做 | 验收标准 |
|---|---|---|---|
| **① 登上去** | 注册/登录 GitHub，接受仓库邀请，配好 git 身份 | 全部 6 人 | `git config user.name` 显示你自己名字 |
| **② 会提交** | 走通一次 改文件 → commit → push → PR | 全部 6 人 | 仓库里有 1 个署你名字的 commit + 1 个你发起的 PR |
| **③ 会生成** | 用 WorkBuddy 生成你负责的那份文档，审完再存 | 每人 1 份 | 你的文件名出现在 `docs/` 或 `web/` 下 |
| **④ 汇总** | 组长 review 全部 PR → 合并 → 打 tag | 组长 | `main` 上 `verify.py` 全绿 + 6 人都有贡献记录 |

> ⚠️ **第 ① 步最容易错**：不要 6 个人共用组长一个账号。
> 每人必须用自己的 GitHub 账号、自己的 `user.name` / `user.email`，否则每条 commit 的作者都显示组长，
> 评分表要的「个人贡献证据」直接归零。

## 第 ① 步 · 登上 GitHub（30 分钟）

### 组长先做（只做一次）

1. GitHub 建 **public** 仓库，名字 `hello-algo-knowledge-graph`
2. Settings → Collaborators → 逐个邀请 5 位组员（记下他们的 GitHub 用户名）
3. 本地推代码：

```bash
cd "…/hello-algo_知识图谱"
git config --global user.name  "你的名字"
git config --global user.email "你的GitHub邮箱"
git add -A
git commit -m "chore(repo): 导入知识图谱正文与仓库骨架"
git remote add origin https://github.com/<你的用户名>/hello-algo-knowledge-graph.git
git branch -M main
git push -u origin main
```

### 5 个人怎么排顺序（⚠️ 别让 5 个人同时开始）

组长只有一双手，同时教 5 个新手，结果是 5 个人都在等。分成三批：

| 批次 | 谁 | 什么时候 | 怎么走 |
|---|---|---|---|
| **第 1 批** | **P4（先遣员）** | 今晚，30 分钟 | 自己从头走到尾，**每卡一次就记一条**到 `docs/踩坑记录.md` |
| **第 2 批** | P2 + P3（结对） | 明天 | 照着 P4 的记录走，两人互相盯，不许直接问组长 |
| **第 3 批** | P5 + P6（结对） | 明天 | 同上 |

**为什么这么排**

- 第一个人的卡点一定最多（装环境、PATH、token、clone 失败……）。让他写下来，后面 4 个人能少踩 80%。
- 两两结对是因为新手的问题 90% 是同一个问题，两个人在群里互相问就能解决，不用都堆到你这里。
- **你只接「卡超过 30 分钟」的求助**，否则 W1 会被救火吃光，你自己的工作全停。

先遣员选 P4，因为他负责「技术方案与验收」那份文档，本来就得摸清整个仓库。你想自己先走一遍也行，那就把 P4 挪到第 2 批。

### 每个组员做（各自在自己电脑上）

1. 打开邀请邮件 / 仓库页面点 **Accept invitation**
2. 装 git（`git --version` 能出版本号即可）与 Python 3.9+
3. **配自己的身份**（这一步不配，后面所有 commit 都不算你的）：

```bash
git config --global user.name  "张三"
git config --global user.email "zhangsan@example.com"   # 必须和你 GitHub 账号一致
```

4. 复制仓库到本地：

```bash
git clone https://github.com/<组长用户名>/hello-algo-knowledge-graph.git
cd hello-algo-knowledge-graph
python tools/verify.py     # 看到 PASS 11 / FAIL 0 才算环境通了
```

**验收**：`python tools/verify.py` 显示 `PASS 11 / FAIL 0`。看不到这句就别往下走。

## 第 ② 步 · 只会 6 条命令就够（40 分钟）

```bash
git pull                          # 1. 先拉最新的，养成习惯
git switch -c feat/你的分支名      # 2. 开自己的分支，不在 main 上改
#  —— 这里改你的文件 ——
python tools/verify.py            # 3. 自己先跑绿
git add 你的文件路径               # 4. 只加自己改的文件，别用 git add .
git commit -m "docs(需求): 补充背景与目标"
git push -u origin feat/你的分支名 # 5. 推上去
#  6. 网页上点 Compare & pull request → 写说明 → Create
```

**只教这 6 条。** `merge` / `rebase` / `stash` / `reset` / `cherry-pick` 一律不用，用到就找组长。

### 三个心智模型

| 概念 | 大白话 |
|---|---|
| `main` | **墙上的版本**——只挂能跑、能演示的东西 |
| 分支 | **你的私人复印件**——改坏了也不会影响任何人 |
| PR | **申请单**——贴到墙上之前，必须有人看一眼 |

### commit 信息格式

```
type(scope): 一句话说清干了什么
```

| type | 什么时候用 | 例子 |
|---|---|---|
| `docs` | 写/改文档 | `docs(需求): 补充第 3 层查找算法说明` |
| `feat` | 加功能 | `feat(检索): 加按章节筛选` |
| `fix` | 修错误 | `fix(数据): 修正 quick_sort 的行数` |
| `chore` | 配置、杂务 | `chore(repo): 初始化仓库` |

**⛔ 四条禁令**：不用 `--date` 改提交时间、不手写/编造 commit hash、不替别人提交、不留到最后一周一次全推。

**验收**：你的 PR 被合并进 `main`，且 `git log --author="你的名字"` 能查到自己的 commit。

## 第 ④ 步 · 汇总与上传（组长，30 分钟）

1. 逐个 PR 看：**文件对不对、有没有跑过 verify、AI 记录真不真** → 写具体意见 → 合并

python tools/verify.py      # 必须 PASS 11 / FAIL 0

3. 打一个标记版本：`git tag v0.1-里程碑1 && git push origin v0.1-里程碑1`

## 卡住了看这里

| 症状 | 原因 | 怎么办 |
|---|---|---|
| `verify.py` 报 FAIL | 改坏了 `data/` 里的数据 | 发我输出的那几行，别自己猜 |
| `ModuleNotFoundError` | 用了不带 tkinter/环境异常的 Python | 装 python.org 官方 3.10+ |
| `push` 要求输密码 | GitHub 已不支持密码 | 用 Personal Access Token 当密码 |
| `update were rejected` | 你的分支落后了 | `git pull` 再推；搞不定就新开分支重来 |
| 看到 `<<<<<<<` | 冲突了 | **不要自己删**，截图发群里，一起解一次就学会了 |
| 中文文件 `git status` 显示乱码 | 编码设置 | `git config core.quotepath false` |

## 三条底线

1. **`main` 上永远是能跑的版本**——课上老师会现场拉 `main` 跑，跑不起来全组掉分。
2. **谁的活谁提交**——这是唯一无法事后补的分数。
3. **AI 生成的东西必须自己读过**——AI 记录里写清「提示词 / 原始输出 / 我怎么审的 / 最后改了什么」四段，缺一段扣一段。
