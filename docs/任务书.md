## 三、环境与身份

组员在**自己电脑**上完成，完成后才能进入第四节。

### 3.1 安装 Git

下载地址 `https://git-scm.com/download/win`，安装时保持默认选项，编辑器的选择项选 VS Code。

安装完成后打开 **Git Bash**（开始菜单搜索 `Git Bash`），输入：

```bash
git --version
```

输出形如 `git version 2.x.x` 即成功。

### 3.2 配置身份（硬性，必做）

```bash
git config --global user.name "真实姓名"
```

```bash
git config --global user.email "GitHub 账号的邮箱"
```

姓名用中文真名，与第五节分工表中的姓名一致。邮箱必须是该 GitHub 账号已验证的邮箱。

未配置此项时，提交记录的作者会取系统的默认用户名，或以组长身份出现，个人贡献证据归零。

核对命令：

```bash
git config --global --list | grep user
```

### 3.3 克隆仓库

```bash
mkdir -p /d/CODE
```

```bash
cd /d/CODE
```

```bash
git clone git@github.com:NULLFALSE-tech/Algorithm-graph.git
```

```bash
cd Algorithm-graph
```

若 `git clone` 卡住或报 `Connection timed out`，改用 HTTPS：

```bash
git clone https://github.com/NULLFALSE-tech/Algorithm-graph.git
```

HTTPS 方式推送时需要 Personal Access Token 代替密码，见 `组员手册_01_环境准备.md` 第七节。

### 3.4 验收

```bash
git rev-parse --show-toplevel
```

```bash
python tools/verify.py
```

```bash
python tools/whoami.py
```

三项都通过才算环境就绪：

| 命令 | 期望输出 |
|---|---|
| `git rev-parse --show-toplevel` | 输出仓库根目录路径，无报错 |
| `python tools/verify.py` | 末行 `汇总：PASS 12  /  FAIL 0` |
| `python tools/whoami.py` | 打印六行姓名，且能查到自己的代号与第二阶段任务 |

`python` 命令不可用时，尝试 `py` 或 `python3`。

### 3.5 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `Permission denied (publickey)` | 未配 SSH 密钥 | 见 `组员手册_01_环境准备.md` 第七节，或改用 HTTPS |
| `Repository not found` | 未接受协作者邀请，或地址拼写错误 | 回到 2.3 |
| `python: command not found` | 未装 Python 或未加入 PATH | 装 python.org 官方版，安装时勾选 Add to PATH |
| `verify.py` 报 `FAIL` | 修改了 `data/` 下的数据 | `git checkout -- data/` 还原，重新执行 |
| `whoami.py` 打印的姓名不是本人 | 3.2 的 `user.name` 未配置 | 重做 3.2 |

## 五、提交规范

### 5.1 说明格式

```
类型(范围): 一句话说清做了什么
```

| 类型 | 用途 | 示例 |
|---|---|---|
| `docs` | 写、改文档 | `docs(req): 补知识原理的复杂度一节` |
| `feat` | 新增功能 | `feat(verify): 加文档图片引用检查` |
| `fix` | 修正错误 | `fix(docs): 修正层内条数写错的一处` |
| `chore` | 配置、杂务 | `chore(repo): 补 PR 模板` |

范围可省略，纯文档类允许写成 `docs: 一句话`。禁止出现 `update`、`修改`、`1`、`fix bug` 等无信息量的说明。

### 5.2 次数与时间分布

| 项 | 要求 |
|---|---|
| 最低次数 | 每人 **3 次** |
| 时间跨度 | 至少跨 **3 个不同日期** |
| 三次的自然节奏 | 首版 → AI 二轮复核后的修改稿 → 按 review 意见补正 |
| 单次体量 | 一次只做一件事，不把整份文档一次推完 |

核对命令：

```bash
git log --author="姓名" --pretty=format:'%ad %s' --date=format:'%m-%d %H:%M'
```

### 5.3 分支命名

| 谁 | 分支名 |
|---|---|
| P2 | `docs/req-knowledge` |
| P3 | `docs/req-visual` |
| P4 | `docs/readme-features` |
| P5 | `docs/demo-script` |
| P6 | `feat/verify-checks` |

不直接提交到 `main`。`main` 上的内容由 PR 合并产生。

### 5.4 三条禁令

| 禁令 | 后果 |
|---|---|
| 不用 `git push --force` | 会覆盖他人提交，历史出现断裂 |
| 不用 `git reset --hard` | 会抹掉未推送的工作 |
| 不用 `--date` 改提交时间 | 属伪造记录，判罚重于时间集中 |

### 5.5 提交前 30 秒自查

```bash
git status --short
```

```bash
git diff --stat
```

```bash
python tools/verify.py
```

三条命令的含义：只提交自己改动的文件、确认改动范围符合自己的职责、确认没有把仓库改坏。
