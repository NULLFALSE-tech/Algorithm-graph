## 零、先搞清这个脚本是什么

`tools/verify.py` 是全组的「裁判」：**谁的 PR 改坏了数据或文档，跑一下就知道，红了就不许合并**。

它现在有 **12 项**检查，覆盖 `data/` 下的数据完整性、源码文件、渲染接口。跑起来长这样：

```
  PASS  字段完整性
  PASS  id 唯一
  ...
 汇总：PASS 12  /  FAIL 0
```

你可以先跑一遍看看（**这是你的基线，必须记住这个数**）：

```bash
cd /d/CODE/Algorithm-graph
python tools/verify.py
python tools/verify.py -v      # -v 会连 PASS 的说明也打出来
```

**它现在管不到文档**：图片引用写成绝对路径、需求文档缺章节，它都不会报。这两项就是你的活。

## 一、项 A（第 13 项）：文档图片引用有效性

扫 `README.md` 和 `docs/*.md` 里所有图片引用（Markdown 里「感叹号 + 方括号说明 + 圆括号路径」那个语法），逐个检查三件事：

1. 引用的文件**真实存在**
2. 是**相对路径**（不能以 `/` 开头）
3. **不含盘符**（不能出现 `C:\` `D:\`——老师明确禁止绝对路径）

### ⚠️ 这里有个坑，我已经替你踩过了

**不能直接对全文做正则**。为什么？因为手册和任务卡里到处是「示例」，比如在代码块里示范 `img/xx.png` 这种写法。你一扫，它就变成「文件不存在的图片引用」，于是第 13 项**永远红**，`PASS 14` 永远达不到。

**解决**：扫之前先把围栏代码块整段剔掉，只扫正文。

而且**不要用 `re.sub(r"```.*?```", ...)`** ——文档里可能出现不成对的反引号，正则配对会错位，一错就把后面的正文吞掉或漏掉。**逐行开关**才稳。

## 二、项 B（第 14 项）：需求文档六块齐全

老师要求需求文档必须有六块：①背景目标 ②知识原理 ③主要功能 ④可视化设计 ⑤技术方案 ⑥团队分工。

### ⚠️ 第二个坑：必须查「标题」，不能查「全文有没有这个词」

需求文档末尾有一张「第二阶段分工表」，里面就写着「补『二、知识原理』」「补『四、可视化设计』」这些字。

如果你用 `k in text` 判断，这两块明明**还没写**，检查却会报绿 —— **假绿比红更危险**，它让人以为没事。

所以只取二级标题（`^## ` 开头的行），在标题里找关键词。

## 三、完整代码（照抄，然后自己跑通）

### 3.1 先加一行 import

`tools/verify.py` 顶部现在有 `import argparse / json / sys / from collections import Counter / from pathlib import Path`，**加一行 `import re`**（放在 `import json` 后面即可）。

### 3.2 两个函数 + 一个工具函数

放在 `main()` 里现有 12 个 `check(...)` 之后、`# ---------- 汇总 ----------` 之前：

```python
    # ---------- 13. 文档图片引用有效性 ----------
    def _md_no_code(text):
        """把围栏代码块整段剔掉，只留正文。

        为什么要剔：文档里到处是「示例」，比如在 bash 块里示范图片写法，
        那不是真引用。全文正则会把它当真的，于是检查永远红。

        为什么逐行开关而不是 re.sub：文档里可能出现不成对的反引号，
        正则的贪婪/非贪婪配对会错位，一错就把后面的正文整段吞掉或漏掉。
        """
        out, fence = [], False
        for line in text.splitlines():
            if line.lstrip().startswith("`" * 3):
                fence = not fence
                continue
            if not fence:
                out.append(line)
        return "\n".join(out)

    def c_doc_img_refs():
        bad = []
        md_files = [ROOT / "README.md"] + sorted((ROOT / "docs").glob("*.md"))
        n = 0
        for p in md_files:
            if not p.exists():
                continue
            for _alt, target in re.findall(r"!\[([^\]]*)\]\(([^)]+)\)",
                                           _md_no_code(p.read_text(encoding="utf-8"))):
                n += 1
                t = target.strip()
                # 形如 ![](img/a.png "这是标题") 的，把后面的标题去掉，只留路径
                t = t.split()[0] if t else t
                # 页面内锚点（如 #第三节）不是文件，跳过
                if t.startswith("#"):
                    continue
                if t.startswith(("http://", "https://")):
                    continue
                if t.startswith("/") or re.match(r"^[A-Za-z]:[\\/]", t):
                    bad.append("%s: 绝对路径 %s" % (p.name, t))
                    continue
                if not (p.parent / t).exists():
                    bad.append("%s: 文件不存在 %s" % (p.name, t))
        assert not bad, "；".join(bad)
        return "扫了 %d 条文档图片引用，全部有效" % n

    check("文档图片引用", c_doc_img_refs)

    # ---------- 14. 需求文档六块齐全 ----------
    def c_req_sections():
        p = ROOT / "docs" / "Project_Requirements_and_Design.md"
        assert p.exists(), "需求文档不存在"
        heads = re.findall(r"^##\s+(.+)$", _md_no_code(p.read_text(encoding="utf-8")), flags=re.M)
        need = ["背景", "知识原理", "主要功能", "可视化设计", "技术方案", "团队分工"]
        miss = [k for k in need if not any(k in h for h in heads)]
        assert not miss, "缺少章节：%s —— 老师要求的六块结构不全" % "、".join(miss)
        return "六块齐全，共 %d 个二级标题" % len(heads)

    check("文档六块齐全", c_req_sections)
```

### 3.3 三个必须注意的细节

| 细节 | 说明 |
|---|---|
| **名字不要叫「图片引用」** | 现有第 5 项已经叫「图片引用」（查的是 `data/imgs` 的真实文件），你这项叫「**文档图片引用**」，一眼能区分 |
| **函数写在 `main()` 里面** | 因为要用到 `main()` 里的 `ROOT`（其实 `ROOT` 是全局的，写在里面只是为了跟现有 12 项保持同一种风格）。照抄就行 |
| **`return` 的字符串只在 `-v` 时显示** | FAIL 时说明一定会打印；PASS 时只有 `python tools/verify.py -v` 才看得到。所以别指望不加 `-v` 也能看见你写的那句 |

## 四、第 14 项现在一定是红的（这是预期，不是你的错）

我跑过一遍，真实的报错是这样：

```
FAIL  文档六块齐全  缺少章节：知识原理、主要功能、可视化设计、团队分工
```

四块都缺，各有归属：

| 缺的章 | 谁负责补 |
|---|---|
| 知识原理 | P2（新增「二」） |
| 主要功能 | P2（把「二、功能与数据」改名为「三、主要功能与数据」） |
| 可视化设计 | P3（新增「四」） |
| 团队分工 | P2（把「附：小组分工」改成「六、团队分工」） |

所以顺序是：

1. 你先写代码，本地跑，**红是正常的**，只要报错信息和上面这行意思一致
2. 发 PR 时在描述里写清楚：「第 14 项当前红属预期，缺的四章分别归 P2/P3，合并后转绿」
3. 等 P2、P3 都合并了，`git pull` 再跑，**这时候必须 PASS 14 / FAIL 0**

这叫「**先立规矩，再补作业**」——规矩先立住，后面的人才有靶子。

## 五、你必须亲手验一次「它能抓错」

一个从不报错的检查，等于没有检查。所以你交之前一定要做这个实验：

```bash
# 1. 造一个假错误：在 docs/ 下建一个临时文件，故意写两个坏引用
cat > docs/_tmp_bad.md <<'EOF'
# 临时测试文件
![](img/不存在的图.png)
![](D:/nope.png)
EOF

# 2. 跑自检 —— 第 13 项必须 FAIL，并且两条都要报出来
python tools/verify.py

# 3. 删掉临时文件（用 rm 删这一个文件，别用通配符）
rm docs/_tmp_bad.md

# 4. 再跑 —— 必须恢复到你加第 13 项之后的状态
python tools/verify.py
#    只加了第 13 项 → 应恢复 PASS 13 / FAIL 0
#    第 13、14 两项都加了 → 应是 PASS 13 / FAIL 1（红的正是第 14 项，属预期）
```

> ⛔ **不要拿 `README.md` 本身做实验**。那样一旦忘了撤销，仓库里就有一条绝对路径，直接违反课程禁令。
> 用临时文件，测完删掉，`git status` 必须是干净的。
>
> 📌 上面那段命令虽然在**代码块里**写了 `D:/nope.png`，但你不用担心它被自己扫到——
> 你写的第 13 项会先**剔除所有围栏代码块**再扫，所以这段示例不参与判定。这也正是为什么要剔除代码块的原因。
