## 一、现有脚本的机制

`tools/verify.py` 是全组的校验入口，现有 12 项检查，覆盖 `data/` 下的数据完整性、源码文件与渲染接口。

运行方式与基线输出：

```bash
cd /d/CODE/Algorithm-graph
```

```bash
python tools/verify.py
```

输出末行为 `汇总：PASS 12  /  FAIL 0`，该数字为基线。

`-v` 参数会同时打印通过项的说明：

```bash
python tools/verify.py -v
```

机制要点：

| 项 | 说明 |
|---|---|
| 注册方式 | 调用 `check("名字", 函数)`，为普通函数调用，不是装饰器 |
| 判定通过 | 函数正常 return，返回值作为说明文字 |
| 判定失败 | 函数 `raise AssertionError("原因")`，原因一定会打印 |
| 说明可见性 | return 的说明仅在加 `-v` 时显示；AssertionError 的原因始终显示 |
| 函数位置 | 现有 12 项均定义在 `main()` 内部，新增项保持同一风格 |
| 现有第 5 项名称 | 「图片引用」，检查的是 `data/imgs` 下的真实图片文件，与文档中的引用无关 |

现有 12 项无法覆盖文档层的问题：图片引用写成绝对路径、需求文档缺章节，脚本都不会报。这两项即本岗位的任务。

| 约束 | 后果 |
|---|---|
| 第 13 项必须先剔除围栏代码块再扫描 | 文档中存在大量代码块内的示例写法，全文匹配会把示例当作真实引用，检查永久报红 |

| 第 13 项须处理带标题的引用与页内锚点 | 引用语法中路径后可能带引号包裹的标题，页内锚点并非文件，两者都会造成误报 |

### 任务群 B · 生成第 13 项

```
我在给一个 Python 自检脚本新增一项检查。脚本只用标准库，风格是：
函数内部 raise AssertionError("原因") 表示失败，正常 return 一句说明表示通过，
外面对每个函数调用一次 check("名字", 函数)。函数定义在 main() 内部。
脚本顶部已经有 import json 和 from pathlib import Path，需要新增 import re。

现有 12 项检查中，第 5 项名为「图片引用」，检查的是 data/imgs 下真实存在的图片文件，
与文档中的图片引用无关。因此新增项命名为「文档图片引用」。

第 13 项「文档图片引用」的规则：
扫描 README.md 与 docs 目录下所有 .md 文件中的 Markdown 图片引用，
逐个检查三项：
① 被引用的文件是否真实存在（相对该 md 文件所在目录解析）
② 是否为相对路径（不能以斜杠开头）
③ 是否含盘符（不能出现形如字母加冒号加斜杠的绝对路径）

两个关键约束，必须满足：
- 扫描前必须先把围栏代码块整段剔除。原因是文档里大量存在写在代码块内的示例写法，
  全文匹配会把示例当成真实引用，导致该项永久失败。
- 剔除代码块必须用逐行开关的方式（维护一个 in_fence 布尔值，遇到以三个反引号开头的行就翻转），
  不能用正则做区块匹配，因为文档中可能出现不成对的反引号，正则配对会错位，
  导致整段正文被吞掉或漏掉。

另外两点细节：
- 引用语法中路径后面可能跟一个用双引号包裹的标题，取值时用空白切分取第一段
- 以井号开头的页内锚点不是文件，直接跳过；以 http 或 https 开头的跳过

要求：
- 只使用标准库 re 与 pathlib
- 不联网，不读环境变量
- 函数返回一个字符串，说明扫描了多少条引用
- 失败时把有问题的文件与路径拼接进一条 AssertionError 消息里，用中文分号分隔

输出完整的函数代码，不要输出整个脚本。
```

拿到代码后，与下面这份参考实现逐点对照。函数名可以不同，四个逻辑点必须一致。

```python
    # ---------- 13. 文档图片引用 ----------
    def _md_no_code(text):
        out, fence = [], False
        for line in text.splitlines():
            if line.lstrip().startswith("`" * 3):
                fence = not fence
                continue
            if not fence:
                out.append(line)
        return "\n".join(out)

    def c_doc_img_refs():
        bad = []
        md_files = [ROOT / "README.md"] + sorted((ROOT / "docs").glob("*.md"))
        n = 0
        for p in md_files:
            if not p.exists():
                continue
            for _alt, target in re.findall(r"!\[([^\]]*)\]\(([^)]+)\)",
                                           _md_no_code(p.read_text(encoding="utf-8"))):
                n += 1
                t = target.strip()
                t = t.split()[0] if t else t
                if t.startswith("#"):
                    continue
                if t.startswith(("http://", "https://")):
                    continue
                if t.startswith("/") or re.match(r"^[A-Za-z]:[\\/]", t):
                    bad.append("%s：绝对路径 %s" % (p.name, t))
                    continue
                if not (p.parent / t).exists():
                    bad.append("%s：文件不存在 %s" % (p.name, t))
        assert not bad, "；".join(bad)
        return "扫描 %d 条文档图片引用，全部有效" % n

    check("文档图片引用", c_doc_img_refs)
```

对照检查四项：是否剔除代码块、是否用逐行开关、是否跳过锚点与网络地址、是否按 md 文件所在目录解析相对路径。

第 14 项「文档六块齐全」的规则：
检查 docs/Project_Requirements_and_Design.md 的二级标题（以两个井号加空格开头的行）中

要求：

- 文件不存在时也要给出明确的中文报错
- 缺失时把缺的章节名用中文顿号连接，拼进 AssertionError 消息
- 通过时返回六块齐全，并给出二级标题总数

输出完整的函数代码与那一行 check 调用。

参考实现：

```python
    # ---------- 14. 文档六块齐全 ----------
    def c_req_sections():
        p = ROOT / "docs" / "Project_Requirements_and_Design.md"
        assert p.exists(), "需求文档不存在"
        heads = re.findall(r"^##\s+(.+)$", _md_no_code(p.read_text(encoding="utf-8")), flags=re.M)
        need = ["背景", "知识原理", "主要功能", "可视化设计", "技术方案", "团队分工"]
        miss = [k for k in need if not any(k in h for h in heads)]
        assert not miss, "缺少章节：%s —— 六块结构不全" % "、".join(miss)
        return "六块齐全，共 %d 个二级标题" % len(heads)

    check("文档六块齐全", c_req_sections)
```

放置位置：`main()` 内现有 12 个 `check(...)` 调用之后、汇总输出之前。同时确认脚本顶部已加入 `import re`（放在 `import json` 之后即可）。

## 三、AI 使用禁区

| 禁止事项 | 具体说明 | 原因 |
|---|---|---|
| 让 AI 修改现有 12 项的逻辑 | 现有项为全组共同约定 | 改动会使他人 PR 意外报红 |
| 让 AI 放宽判定标准 | 例如把「文件不存在」降级为提示而不报错 | 检查失去意义，等同于未写 |
| 让 AI 引入第三方库 | requests、pillow 等一律不引入 | 项目要求仅用 Python 标准库，保证机房环境可运行 |
| 让 AI 在检查中联网 | 不发起任何网络请求 | 评阅机器可能无网络，会直接报错 |
| 让 AI 直接提交未经运行的代码 | 每段代码必须本地跑通并做造错实验 | 未运行的代码无法证明其有效 |
| 让 AI 顺带重构其他函数 | 只追加两项，不改动现有代码风格 | 超出范围，增加 review 与合并成本 |
